# 数据规范

当前正式服务仅探测依赖状态，无用户业务表；隔离记录示例使用内存存储。以下数据合同要求适用于新增或变更的数据，未启用项作为启用前条件。

## DATA-01 数据合同
新增实体必须在对应OpenSpec变更中列出字段、类型、必填性、默认值、长度/取值范围、唯一约束、主体归属、时间格式和删除语义。现有记录示例的title、幂等键及响应约束以[后端规范](backend.md)和[接口规约](../../openspec/specs/extension-contract/spec.md)为准，不另设数值。
检查：用缺失、空值、非法类型、上下界和重复键测试逐项核对合同；拒绝必须发生在写入之前。无合同或实现与合同不一致时阻止合并。

## DATA-02 分类与隔离
公开仓库只保存代码、结构定义及合成测试数据。真实个人资料、凭据、数据库导出和生产数据不入库、不进入镜像或日志。测试使用独立存储、项目名和端口，不复用主实例数据；不同主体的记录与幂等键不得串用。
检查：审阅`git diff --cached`、`.gitignore`、`.dockerignore`和测试配置；运行秘密检查及接口的跨主体访问、并发幂等用例。记录示例须验证同主体同键只创建一条、不同主体互不影响。发现混用停止操作，保留现场并评估泄露范围。

## DATA-03 迁移与恢复
新增持久化结构时，使用有版本的迁移文件；在变更中写明新旧版本兼容关系、备份与恢复命令、失败中止条件。执行顺序为扩展→迁移→收缩，破坏性操作须另行明确批准。不能以应用版本回退替代数据库恢复验证。
检查：在隔离数据副本上验证升级、重复执行的处理、失败恢复与旧版本兼容，比较迁移前后的记录数及关键字段/约束。未有成功证据时不得执行正式迁移。当前无业务迁移，不声称已完成业务数据恢复演练。

## DATA-04 生命周期
接入真实数据前，必须在规约中指定来源与使用依据、访问角色、保留期限、删除触发条件、备份保留期限及删除验证方法；未定义不得采集。删除须同时考虑主库、索引、缓存和备份的到期处理。
检查：以合成记录测试到期/主动删除后不可检索、跨主体不可访问及备份到期策略；恢复后不得重新暴露已要求删除的数据。当前测试卷默认保留，清理需确认项目名和数据范围，不使用无范围删除命令。
