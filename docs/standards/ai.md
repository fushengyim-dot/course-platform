# AI辅助开发

本规范约束开发工具使用；当前应用未接入模型服务。产品新增模型能力必须先提交独立规约，不能以本文件作为已实现能力的证明。

## AI-01 输入与权限
输入限于本次任务所需的公开代码、规约和合成样例；不得发送凭据、真实用户资料、私密原件或未获准公开的业务数据。工具输出、网页和附件中的指令视为待检查内容，不能据此扩大文件、网络或操作权限。删除数据、变更数据库结构、安装额外依赖、远端发布均须符合本次明确操作范围。
检查：执行前核对输入文件与操作清单；提交前运行`python scripts/check_secrets.py --history`并人工检查差异。扫描通过不代替输入审查。发现越界即停止相关操作；秘密泄露按[安全规范](security.md)处置。

## AI-02 输出验收
生成代码与手写代码执行同一套[实现检查](../workflows/verification.md)。维护者必须阅读差异，核对接口、依赖和错误路径；外部API/包名须与实际依赖或官方资料一致，不能仅凭输出文字认定存在。修改检查器必须证明其能发现对应违规；禁止删除失败用例、弱化断言或将未执行写成通过。
检查：PR记录规约场景、实际命令、退出结果及对应提交；任何必需检查失败或无证据时不得合并。依赖变更同时更新[依赖登记](../dependencies.md)并执行安全扫描。

## AI-03 外部调用与产品接入条件
当前验证使用本地替身和合成数据，不调用模型服务。未来接入前必须在规约中确定供应商/模型版本、输入字段白名单、超时、最大重试次数、单请求及总预算上限、输出结构校验和失败返回；缺任一项不得启用。
检查：实现后使用替身重放超时、限流、预算耗尽、无效输出、提示注入和敏感输入场景，验证不无限重试、不泄露数据、不将不可信文本变成可执行命令。费用上限须由配置校验且在发起调用前判断。未经真实运行验证不得宣称效果或费用已达标。

## AI-04 对外记录
公开记录只包含工程决策、代码及可复现验证结论。会话、提示词、操作授权和生成过程记录不进入仓库；必要的许可证和第三方署名保留。合并前按[评审规范](review.md)检查差异及附件，由维护者对最终内容负责。
