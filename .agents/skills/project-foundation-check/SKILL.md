# 项目基础与交付检查

## 作用范围
只在本skill所在项目根目录操作。先确认git根、远端与README一致；不复制到全局目录。不授予新建仓库、历史重写、发布、部署或发送消息的权限，按当前用户授权执行。本skill属于项目工程资料，可随项目源代码版本管理；不得将TASKS、HANDOFF、会话授权或其他内部备注一并上传。

## 开始前
读取TASKS.md、README.md、AGENTS.md、docs/standards/README.md索引及八类规范、openspec/specs和对应活动变更；优先使用现有docs/workflows/verification.md及release.md，避免复制成分叉规范。任务与内部证据写入被忽略的internal目录。按本次改动选择必要检查，不因旧记录通过而默认当前版本通过。

## 实现验收
- 场景映射正常、失败和边界用例；接口检查分层、统一响应、默认拒绝、主体归属、输入边界及需要时的并发幂等。
- 按README运行一键测试；改动检查器时用真实违规注入证明检查确实失败，随后恢复。失败修实现，不削弱断言。
- 故障测试必须确认被测实例正在运行。连接失败或进程不存在不能冒充错误密码等预期故障的证明。
- 页面变更实际检查导航、窄屏、键盘、加载、失败、恢复；工具无法操作的项目单列未验证。
- 含日期日历的公开信息功能，按规约先确认日期代表预计发布时间、来源发布日期还是活动日期；验证跨月切换、同日多条/多校聚合、无日期记录不误入日历、空日期提示，以及所选日期下学校/院系/标题/链接与只读接口相符；非法月份应返回参数错误。
- openspec validate --all --strict --no-interactive；全部必需场景验证后才归档。

## 版本与复现
- python scripts/check_secrets.py --history；核对暂存内容、历史、构建上下文和git忽略，内部备注、凭据、个人原始材料不上传。
- 用scripts/verify_release.py在独立目录、项目名和端口启动指定提交；需要Python3.12+。密码临时随机生成，不打印。
- 存在两个已验收版本时使用--previous演练上一版→当前版→上一版，保存实际SHA、健康结果与耗时；结束停止自己的验证服务，保留数据卷。不操作业务数据迁移。
- 独立聊天复核、干净机器自动验证、真人同伴操作是三种不同证据，不互相冒充。创建新聊天须有用户授权。

## GitHub交付（仅在已授权范围）
- 按目的拆分真实提交，功能、修复、文档分清；不为数量拆碎，不伪造协作者。feature分支→PR→同一head SHA的verify成功→合并。
- 查询当前main保护规则与检查状态。若需实测必须PR规则，使用无关联PR的真实改动测试拒绝；已有合格PR分支的本地合并被允许不是绕过证据。
- 保持中性提交作者。网页合并邮箱不兼容时，在符合保护规则且检查通过的现有PR上本地合并；不关闭规则或强制推送绕过。
- 不把force push当作远端旧对象已消失；敏感历史迁移须单独授权，先备份校验、旧库私密保留，再核验新库对象与公开页面。
- 公开说明面向开发者，只写实际行为、必要限制、验证方法；会话授权、来源整理、内部待办留本地。依赖许可证与第三方署名不得随意删除。

## 四维规范复核
适用于规范新增、整体规则验收或按评分表复查；不以文件数量替代实质覆盖。不在公开文档保留评分备忘录。

1. A 落位与可加载（30）：确认Git根的AGENTS入口、规范索引和链接真实存在；按实际工具检查格式。AGENTS不机械套用Cursor的globs/alwaysApply；SKILL检查name/description和结构。区分文件可读、当前会话已加载、独立新会话发现三种证据；忽略的本地skill不能充当公开仓库证据。
2. B 规范覆盖（20）：逐项核对产品、后端、安全、测试、运维、AI、数据、评审；对每类记录权威路径、实质条款和缺口。允许跨文档引用但不能只有标题。正式AI工程规范可公开，内部授权/会话/生成过程不公开。未来启用条件与当前已实现能力分列。
3. C 可判定性（30）：从每类规则抽查并覆盖关键风险，定位适用条件、明确阈值或通过条件、检查步骤、失败处置和证据；建立规则/规约场景→测试或人工步骤→提交→实际结果链。人工审批不得冒充自动强制，结构校验不得冒充功能测试，未执行不能判通过；改动检查器时验证真实违规会被发现。
4. D 组织与自治（20）：核对入口→权威规范→能力规约/变更→工作流→评审→归档/版本记录，检查空壳、重复定义、失效引用与矛盾状态。例外须有范围、理由、责任人、期限、补偿检查及关闭条件；安全越界及必需检查失败不得以例外放行。

输出每维事实、证据、缺口与下一步到internal；当前状态直接更新TASKS，原依据另留历史。只有各项必要验收满足才关闭本批；未有教师细项扣分规则不编造精确分数。工程基础、规范覆盖、完整产品、教学平台提交分别判定。复核不是自动扩大为补功能、公开发布或新建聊天的授权。

## 交付判定
先核对总目标，再逐项核对证据、格式、读者与公开边界。记录当前提交/标签、运行链接、未完成项。教师提交、完整业务功能、工程基础分别判定；没有平台回执不得说已交作业。生成作业图片时按实际允许格式，地址可读，二维码须核验，内部制作记录不进图片。
