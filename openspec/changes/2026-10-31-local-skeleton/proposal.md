# Why
项目需要一个可重复启动、可诊断的基础工程，使后续功能开发能够在一致的运行环境中进行。状态页与健康检查为开发者提供统一的环境检查入口，减少手动排查应用与依赖的步骤。

## What Changes
- 建立独立仓库、五类工程规范及最小运行骨架。
- 实现系统状态页、配置校验、健康和存活接口、结构化日志、容器编排及测试。
- 采用独立的最小工程，避免迁入既有应用的业务耦合和运行数据。
- 采用按能力增量开发的方式，替代一次性生成全部业务；登录、业务读写和额外外部服务不属于此变更。

## Capabilities
### New Capabilities
- `runtime-foundation`: 可独立启动、可观测且默认拒绝未登记 API 的基础工程。

## Impact
新增 frontend/backend/deploy/scripts/docs/openspec 目录及配置文件。服务仅在本机开放入口，不涉及生产数据迁移。
